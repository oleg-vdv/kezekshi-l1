# kezekshi-l1 – локальный L1-аналитик SOC поверх Wazuh

**kezekshi** (каз. _кезекші_ – дежурный) – контур первичного разбора алертов, который
работает на своей машине и не отправляет данные наружу. Детерминированные правила снимают
операционный шум, а неоднозначный остаток разбирает дообученная Gemma 4 E2B (Apache 2.0) и
готовит карточку для второй линии: вердикт, утверждения со ссылками на доказательства,
техники MITRE ATT&CK, чего не хватает и что проверить.

> В режиме `assist` модель ничего не закрывает. Сам контур закрывает только
> детерминированный шум из белого списка, всё остальное смотрит человек.

**Что здесь есть:** код контура, схема ответа, индекс ATT&CK, скрипты обучения и оценки,
руководство оператора. **Веса:** [oleg-vdv/kezekshi-l1 на Hugging Face](https://huggingface.co/oleg-vdv/kezekshi-l1).
**Чего нет:** обучающих данных (см. [ниже](#веса-и-данные)).

## Цифры

Замеры на закрытом наборе, 06.11.2026, температура 0, без размышления, решение модели без
страховочных правил. Полный контур дополнительно страхует её памяткой правил.

| тест | вердикт | атаки подняты в L2 | ложные эскалации | MITRE, полнота | MITRE, точность | брак ответа |
|---|---|---|---|---|---|---|
| знакомые типы (76) | 73/76 | 42/42 | 1/34 | 74/86 | 74/82 | 1/76 |
| типы вне обучения (20, 5 семейств) | 13/20 | 20/20 | – | 25/36 | 25/34 | 0/20 |
| реальный шум стенда (100) | 93/100 | – | 1/100 | – | – | 0/100 |

На потоке лабораторного стенда (замер на 3000 алертах) 98,1 % алертов решается без вызова
модели, в модель уходит 1,9 %. Модель отвечает за 2–5 секунд на алерт на ноутбуке с 8 ГБ
видеопамяти.

**Что эти цифры не доказывают:**

- Recall на реальных атаках не измерен: в реальном наборе только шум. 20/20 получено на
  пяти семействах, это мало.
- 30 из 76 знакомых и 63 из 100 реальных кейсов совпадают с обучением с точностью до цифр.
  Вне этих совпадений вердикт на прежней схеме был 44/46 и 34/37.
- Реальный шум почти целиком закрывается белым списком до модели, поэтому эта строка
  не описывает тот хвост, где модель работает в контуре.
- Эталон реального шума – суждение одного аналитика, а не решения дежурной смены.

Вывод пока такой: контур годится как разгрузка от шума и черновик карточки. Как автономный
решатель эскалаций модель не проверена.

## Что оказалось важным

- **Синтетика не переносится на реальный поток.** На чистой синтетике было 0 ложных
  эскалаций, на реальном шуме та же версия эскалировала 39 из 100. Дообучение на 215
  реальных benign-кейсах убрало это.
- **Трудные негативы работают лучше новых типов атак.** PowerShell `-enc` из SCCM,
  `vssadmin create` от бэкапа, скан по заявке: на таких примерах модель учит грань по
  признакам, а не по поверхности.
- **Жёсткая схема дешевле дообучения.** Схема Ollama собирается под каждый алерт: разрешены
  только его E-id и кандидаты MITRE. Без переобучения брак на типах вне обучения упал с 9/20
  до 0/20, а полнота MITRE выросла с 13/36 до 25/36. Плата: вердикт на реальном шуме
  снизился с 97 до 93 (в основном путаница FP и BTP), появились единичные лишние эскалации,
  а проверка ссылок теперь формальна.
- **Подсказка влияет на вердикт.** Список кандидатов MITRE подталкивает модель к эскалации.
  Оговорка «кандидаты не означают атаку» убрала часть этого, но recall на новых типах упал
  с 20/20 до 18/20: OAuth-согласие и IDOR закрылись как штатные. Оговорку мы отвергли.
- **Размышление дообученной модели вредит:** рабочий режим – без него.

## Как устроено

```
Wazuh (только чтение) → normalize → инъекция? шум из белого списка? ─ да → решено без модели
                                              │ нет
                                              ▼
                     кандидаты MITRE → модель → валидатор → политика → очередь L2 и аудит
```

```
src/triage.py        системный промпт, схема ответа под алерт, клиент Ollama, валидатор
src/attack.py        локальный индекс ATT&CK и подбор кандидатов по тексту алерта
src/rulebook.py      памятка правил Wazuh и белый список шума
src/build.py         сборка датасета, src/seed_example.py – образец разметки
src/train_hf.py      дообучение LoRA (transformers + peft), merge_hf.py – склейка
eval/run_eval.py     оценка: вердикт, эскалация, MITRE, проверка ответа
eval/recall_eval.py  recall контура на управляемых атаках
pipeline/            сервис: демон, политика, очередь L2, веб-пульт, отчёты
docs/operations.md   руководство оператора, docs/dataset.md – данные и как собрать свои
```

## Запуск

Нужны Python 3 и Ollama. Сервис работает на стандартной библиотеке. Веса занимают 4,9 ГБ,
проверено на Ollama 0.40.14.

```bash
# Модель из Hugging Face
hf download oleg-vdv/kezekshi-l1 --local-dir kezekshi-l1-v6
(cd kezekshi-l1-v6 && ollama create kezekshi-l1-v6 -f Modelfile)

# Офлайн-проверки без модели
python eval/test_schema.py

# Контур на примерах из репозитория, без Wazuh
cd pipeline
MODEL=kezekshi-l1-v6 OLLAMA=http://localhost:11434/api/chat python run.py --dry-run samples/wazuh_alerts.sample.jsonl
```

Подключение к Wazuh, режимы политики и работа службы описаны в
[docs/operations.md](docs/operations.md) и [pipeline/README.md](pipeline/README.md).

Обучение своей версии:

```bash
cd src && python build.py
python train_hf.py ../data/train.jsonl
python merge_hf.py kezekshi-l1-lora kezekshi-l1-merged
python llama.cpp/convert_hf_to_gguf.py kezekshi-l1-merged --outtype q8_0 --outfile kezekshi-l1-q8_0.gguf
ollama create kezekshi-l1 -f ../Modelfile
```

Заметки по обучению на 8 ГБ: Unsloth на связке Gemma 4 E2B, Windows и выгрузки слоёв в RAM
ломает обратный проход, поэтому здесь `transformers + peft`. Ollama на Windows не
импортирует Gemma 4 из safetensors, нужен перевод в GGUF через llama.cpp.

## Веса и данные

Веса v6 (GGUF Q8_0) опубликованы на
[Hugging Face](https://huggingface.co/oleg-vdv/kezekshi-l1). Датасет не опубликован: он опирается
на материалы учебного курса и на алерты закрытого стенда. Поэтому модель можно запустить и
проверить на своих алертах, но метрики выше из открытых файлов не воспроизвести. Подробнее и
как собрать свой набор – [docs/dataset.md](docs/dataset.md).
